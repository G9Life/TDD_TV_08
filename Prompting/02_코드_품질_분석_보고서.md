## 핵심 진단

`TVController`는 **숫자 입력·채널 검증·Tuner 연동·선호 채널·검색 목록·리모컨 디스패치**를 한 클래스에 모아 **SRP**가 약하고, 새 키/탐색 모드 추가 시 `pushButton`·Up/Down 분기를 직접 고쳐야 해 **OCP**도 약합니다. `MIN_CHANNEL`/`MAX_CHANNEL` 상수는 이미 양호하지만, `handleDigit`의 **`2`**, `handleChannelSearch` 루프 상한 등은 **매직 넘버**로 남아 있습니다.

가장 큰 스멜은 **`handleChannelUp` / `handleChannelDown` / `handleNextFavorite`의 정렬 벡터 + bound + 래핑 중복**입니다. `pushButton`·`handleChannelSearch`는 **Long Method / 조건문 복잡도**가 있습니다. `isDigitOrConfirm`은 **미사용·헤더 미선언 Dead Code**입니다.

## 리팩토링 우선순위 (1~5)

1. **정렬 목록 순환 공통화** — 중복·불일치 위험이 가장 큼, diff 작음  
2. **숫자 입력 상태 분리** — 요구사항 1번 규칙이 가장 복잡  
3. **`pushButton` 테이블 디스패치** — OCP·가독성  
4. **`handleChannelSearch` 분해 + 상수·검증** — Long Method·방어 코드  
5. **Dead code, Tuner 수명, 즐겨찾기 insert 최적화** — 동작 변경 없는 정리  

## C++17 개선 요약

- **전략:** `LinearRangeNavigator` vs `SortedListNavigator`로 Up/Down/NextFavorite 통합  
- **`variant`/`optional`:** 탐색 모드·`processingCH` 상태를 타입으로 표현
